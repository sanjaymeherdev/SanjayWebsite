Installation

Folder Structure After Install

After purchasing, download the zip, extract it, and copy the addons/ folder into your Godot project root.

res:// ├── addons/ │ └── unity_ads_plugin/ │ ├── UnityAds.gd ← wrapper (autoloaded as UnityAds) │ ├── unity_ads_plugin.gd ← export plugin │ ├── plugin.cfg ← plugin manifest │ ├── *.gd.uid ← Godot 4.4+ ID files — keep them │ └── plugin/ │ └── unityadsplugin-release.aar ├── android/ ├── scenes/ └── project.godot
ℹ️
The folder name must stay unity_ads_plugin — the AAR path is hardcoded in the export plugin.

Autoload, not a scene node

UnityAds is a global autoload (singleton). Enabling the plugin registers it for you (check Project Settings → Globals → Autoload). You call it from any script as UnityAds.initialize(), UnityAds.show_interstitial() and so on.

🚨
Do not also drag UnityAds.gd into a scene as a Node. A second copy connects to the native plugin again, and every signal fires twice. It also has no _ready() timing guarantee relative to your own scene. Use the autoload only.
ℹ️
Android only. The native plugin exists only in Android builds. In the editor or on desktop, UnityAds still exists but every call just prints "Plugin NOT found" and does nothing. Test ads on a real Android device.

Enable the Plugin

  1. Open your project in Godot 4.4
  2. Go to Project → Project Settings → Plugins
  3. Find UnityAdsPlugin in the list and toggle it ON
  4. Godot automatically adds UnityAds as a global autoload singleton
🖼️

Screenshot: Project Settings → Plugins → UnityAdsPlugin enabled

✅
Big difference from AdMob: This plugin automatically injects all required Android permissions and Unity Ads Activity declarations into your manifest at build time. No manual manifest editing needed.

Unity Dashboard Setup

Get Your Game ID

  1. Go to cloud.unity.com and sign in
  2. Select your project (or create a new one)
  3. Go to Monetization → Ad Units in the left menu
  4. Your Game ID is shown at the top of this page — copy it
  5. Open UnityAds.gd and replace the GAME_ID constant
addons/unity_ads_plugin/UnityAds.gd — constants at the top of the file 
# Replace with your real Game ID from Unity Dashboard
const GAME_ID = "YOUR_GAME_ID_HERE"
const TEST_MODE = true   # set false for production build

Requirements Checklist

⚠️
Versions above are for Godot 4.4. The JDK and Android SDK / Build-Tools versions are the defaults for that release. On a newer Godot (4.5, 4.6, 4.7…) the required JDK and SDK versions can change, so check the Android export page in the official Godot docs for your version, and do a clean Gradle build after changing editors.

A. Install JDK 17 and the Android SDK

  1. Install JDK 17 (Temurin or OpenJDK 17). Verify in a terminal with java -version — it should print 17.x
  2. Install the Android SDK, either through Android Studio → SDK Manager or the command-line tools
  3. In the SDK Manager, install Android SDK Platform 35, Build-Tools 35.0.1, Platform-Tools and Command-line Tools
  4. If Godot asks for extra SDK components (such as NDK or CMake) during setup, install the versions it names
Terminal — command-line install (optional) 
# Run from your cmdline-tools/latest/bin folder
sdkmanager "platform-tools" "platforms;android-35" "build-tools;35.0.1" "cmdline-tools;latest"
sdkmanager --licenses
⚠️
Do not use JDK 21 or newer. Godot 4.4's Gradle setup expects JDK 17. If your system default is another version, that is fine — Godot uses the path you set in Editor Settings (next step), not the system default.

B. Point Godot at the JDK and SDK

  1. Open Editor → Editor Settings → Export → Android
  2. Set Java SDK Path to your JDK 17 folder (the folder that contains bin)
  3. Set Android SDK Path to your Android SDK folder
  4. Set the Debug Keystore, user and password (see the keystore section below)
🖼️

Screenshot: Editor Settings → Export → Android — Java SDK Path and Android SDK Path

C. Create Keystores

Use keytool from your JDK 17 bin folder.

Terminal — release keystore (keep this file safe) 
keytool -genkey -v -keystore release.keystore -alias my_alias -keyalg RSA -keysize 2048 -validity 10000
Terminal — debug keystore (only if you don't have one) 
keytool -keyalg RSA -genkeypair -alias androiddebugkey -keypass android -keystore debug.keystore -storepass android -dname "CN=Android Debug,O=Android,C=US" -validity 9999 -deststoretype pkcs12
🚨
Back up your release keystore and its passwords. If you lose them you cannot publish updates to the same Play Store app.

D. Android Export Preset

  1. Go to Project → Export → Add… → Android
  2. Turn on Use Gradle Build
  3. Set Min SDK to 24 or higher
  4. Under Architectures, enable arm64-v8a (add armeabi-v7a if you support older devices)
  5. Enable the INTERNET and ACCESS_NETWORK_STATE permissions
  6. Fill in the Release keystore, user and password

E. Export the Build

  1. In the Export dialog, uncheck "Export With Debug" for a release build
  2. Click Export Project… (not One-Click Deploy) and choose a file name
  3. Choose APK for direct install and testing, or AAB for Play Store upload (AAB needs Gradle Build, which you already enabled)
  4. Wait for Gradle. The first build is slow because it downloads Gradle, the Unity Ads SDK and other dependencies
  5. Install the APK on a real Android device and test with TEST_MODE = true first
🚨
Before you publish:

1. Use a Release Keystore and export a Release build via Project → Export. Do NOT use One-Click Deploy.

2. Set TEST_MODE = false in UnityAds.gd and use your real Game ID.

ℹ️
For any other build failure, copy the full Gradle output from Godot's output panel. The first "What went wrong" block usually names the exact problem.

Using the Ads

3 Ad Types Available

📌

Banner

320×50 strip. Top or bottom. Displays automatically after load_banner() succeeds.

🖥️

Interstitial

Full-screen. Auto-reloads after closing or failed show.

🎁

Rewarded

Video with reward. Fires on_rewarded_earned on completion.

Call Order — initialize → load → show

🚨
Always wait for on_initialization_complete before loading ads. And always wait for on_*_loaded before showing. The wrapper has built-in guards — calling show_interstitial() before it's ready just prints a warning and does nothing.
boot_scene.gd — complete example (Godot 4 syntax) 
extends Node

# Load these from YOUR consent screen / saved settings. Never hardcode true.
var has_gdpr_consent := false
var has_privacy_consent := false

func _ready() -> void:
    # 1. Connect ALL signals first, before calling initialize()
    UnityAds.on_initialization_complete.connect(_on_ads_ready)
    UnityAds.on_initialization_failed.connect(_on_ads_failed)

    UnityAds.on_interstitial_loaded.connect(_on_interstitial_loaded)
    UnityAds.on_interstitial_completed.connect(_on_interstitial_completed)
    UnityAds.on_interstitial_failed_to_load.connect(_on_interstitial_failed)
    UnityAds.on_interstitial_failed_to_show.connect(_on_interstitial_failed_to_show)

    UnityAds.on_rewarded_loaded.connect(_on_rewarded_loaded)
    UnityAds.on_rewarded_earned.connect(_on_reward_earned)
    UnityAds.on_rewarded_failed_to_load.connect(_on_rewarded_failed)
    UnityAds.on_rewarded_failed_to_show.connect(_on_rewarded_failed_to_show)

    UnityAds.on_banner_loaded.connect(_on_banner_loaded)
    UnityAds.on_banner_failed_to_load.connect(_on_banner_failed)
    UnityAds.on_banner_clicked.connect(_on_banner_clicked)

    # 2. Pass the player's real consent choice (call before initialize)
    UnityAds.set_consent(has_gdpr_consent, has_privacy_consent)

    # 3. Initialize ONCE per app launch — uses GAME_ID + TEST_MODE from UnityAds.gd
    if not UnityAds.is_initialized():
        UnityAds.initialize()
    else:
        _on_ads_ready()

func _on_ads_ready() -> void:
    print("Unity Ads ready — loading all ad types")

    # 4. Load ads AFTER init completes — not before
    UnityAds.load_interstitial()
    UnityAds.load_rewarded()
    UnityAds.load_banner("bottom")  # "top" or "bottom"
    # Banner displays automatically once on_banner_loaded fires

func _on_ads_failed(error: String, message: String) -> void:
    print("Unity Ads init failed: ", error, " — ", message)

# ── Banner ──────────────────────────────────────────────────────
func _on_banner_loaded(placement_id: String) -> void:
    print("Banner visible: ", placement_id)
    # No extra call needed — banner is already showing

func _on_banner_failed(placement_id: String, error: String) -> void:
    print("Banner failed: ", error)

func _on_banner_clicked(placement_id: String) -> void:
    print("Banner clicked: ", placement_id)

func toggle_banner(show: bool) -> void:
    if show:
        UnityAds.load_banner("bottom")   # loads and shows automatically
    else:
        UnityAds.hide_banner()

# ── Interstitial ────────────────────────────────────────────────
func _on_interstitial_loaded(placement_id: String) -> void:
    print("Interstitial ready: ", placement_id)

func _on_interstitial_failed(placement_id: String, error: String, message: String) -> void:
    print("Interstitial load failed: ", error)

func on_level_complete() -> void:
    if UnityAds.is_interstitial_ready():
        UnityAds.show_interstitial()
        # Do NOT change scene here — wait for completed OR failed_to_show
    else:
        change_scene()   # Ad not ready — proceed without it

func _on_interstitial_completed(placement_id: String) -> void:
    # Ad closed by user — now safe to change scene
    # UnityAds.gd auto-reloads interstitial here
    change_scene()

func _on_interstitial_failed_to_show(placement_id: String, error: String, message: String) -> void:
    # The ad never appeared, so on_interstitial_completed will NOT fire.
    # Continue anyway or the player is stuck on this screen.
    print("Interstitial failed to show: ", error)
    change_scene()

# ── Rewarded ────────────────────────────────────────────────────
func _on_rewarded_loaded(placement_id: String) -> void:
    print("Rewarded ready: ", placement_id)

func _on_rewarded_failed(placement_id: String, error: String, message: String) -> void:
    print("Rewarded load failed: ", error)

func offer_revive() -> void:
    if UnityAds.is_rewarded_ready():
        UnityAds.show_rewarded()
        # Reward is given in _on_reward_earned, NOT here
    else:
        print("Rewarded not ready yet — requesting a new load")
        UnityAds.load_rewarded()   # safe fallback, see note below

func _on_rewarded_failed_to_show(placement_id: String, error: String, message: String) -> void:
    print("Rewarded failed to show: ", error)
    # Tell the player the ad isn't available — do NOT give the reward

func _on_reward_earned(placement_id: String) -> void:
    # Only fires when user COMPLETES the video — safe to give reward
    # UnityAds.gd auto-reloads rewarded here
    give_player_coins(100)
⚠️
Godot 4 signal syntax changed from Godot 3. Always use the dot syntax:
✓ UnityAds.on_rewarded_earned.connect(_on_reward_earned)
✗ UnityAds.connect("on_rewarded_earned", _on_reward_earned)

Notes on the Example

⚠️
Initialize once, not in every scene. Put the code above in your first (boot) scene or in another autoload. Calling initialize() again in each scene re-runs the SDK start-up and stacks up signal connections. The is_initialized() check in the example guards against this.
⚠️
Rewarded: don't rely on auto-reload alone. UnityAds.gd reloads the rewarded ad after on_rewarded_earned and after a failed show. If a player skips or closes the video early, neither signal fires, so nothing triggers a new load and is_rewarded_ready() stays false. Call load_rewarded() whenever your "watch ad" button is pressed while the ad is not ready (as offer_revive() does above), and verify this behaviour on a real device.
⚠️
Consent. set_consent(gdpr_consent, privacy_consent) takes two booleans: the player's GDPR consent and their privacy-law consent. Pass the real answer from your own consent screen. Do not hardcode true. If your game is aimed at children, check Unity's child-directed / COPPA requirements and the Play Console families policy before you ship ads.
ℹ️
Don't spam interstitials. Show them at natural breaks (level complete, game over), not at app launch or mid-gameplay. Rewarded ads should always be the player's choice.

ℹ️
Auto-retry is built in. If interstitial or rewarded fails to load, the plugin automatically retries after 5 seconds — you don't need to write any retry logic yourself. Note that the retry has no limit: with no fill it keeps trying every 5 seconds, so on a very new app you will see repeated failed-to-load messages in the log. That is normal, but you can cap it by editing the await retry lines in UnityAds.gd if you want.

Debugging & Common Issues

⚠️
Before debugging: Confirm you are testing on a real Android device with a Gradle build. Ads never run in the editor or on desktop. A debug build is fine for testing with TEST_MODE = true.

Step-by-Step Diagnostic — Ads Not Showing

STEPWHAT TO CHECK
ST 1
Correct method
 Use the singleton correctly. Call UnityAds.show_interstitial() not a local variable. Check UnityAds.is_interstitial_ready() returns true before showing. If it returns false, the ad hasn't loaded yet — wait for on_interstitial_loaded signal.
ST 2
Unity dashboard stats
 Unity Ads takes time to serve real ads. Open Unity Dashboard → Monetization → Reporting. Check if ad requests are arriving. Zero requests means the SDK isn't initializing properly. Low fill rate is normal in the first days.
ST 3
Play Store listing
 Real ad fill is usually poor until your app is live. Test ads (TEST_MODE = true) do not need a Play Store listing. For real ads, expect low or no fill for a brand-new or unpublished app, and add your store details in the Unity dashboard once the app is published.
ST 4
TEST_MODE check
 Confirm TEST_MODE matches your build type. TEST_MODE = true shows dummy ads (good for development). TEST_MODE = false required for real revenue in production APK.

Unity Ads vs AdMob — Which to Use?

🎮 Unity Ads — Best For

  • Games with young / gaming audience
  • Rewarded video heavy monetization
  • Simpler setup (no manifest editing)
  • Strong fill rate for game genres

📊 AdMob — Best For

  • Maximum ad variety (5 ad types)
  • Mediation across all networks
  • Higher CPM for general apps
  • Better analytics via Firebase

Mistakes to Avoid

The 18 Mistakes That Break Most Setups

Almost every "my ads don't work" report comes from one of these. Skim the list before you export, and again before you publish.

1

Adding UnityAds.gd to a scene as well as the autoload

A second copy connects to the native plugin again, so every signal fires twice (double rewards, double scene changes).

Do this instead: Use only the UnityAds autoload that the plugin registers.

2

Exporting without Gradle Build or the Android build template

The .aar cannot be bundled, so the app crashes on launch or the singleton is never found.

Do this instead: Install the build template, turn on Use Gradle Build in the Android preset, and reinstall the template after every Godot upgrade.

3

Using the wrong JDK, SDK or Min SDK

JDK 21+ with Godot 4.4 gives Gradle errors, and a Min SDK below 24 breaks the manifest merge.

Do this instead: Use JDK 17 for Godot 4.4, set Min SDK to 24 or higher, and check the Godot docs for the versions your editor needs.

4

Hand-editing AndroidManifest.xml to add Unity activities or permissions

The export plugin already injects them, so your copy causes a Manifest merger failed error.

Do this instead: Remove manual copies and let the plugin do it.

5

Releasing with TEST_MODE = true

You get test ads and no revenue.

Do this instead: Set TEST_MODE = false in UnityAds.gd before your release export, and set it back to true for development.

6

Clicking your own live ads

Self-clicks look like invalid traffic and can get your Unity account flagged.

Do this instead: Test with TEST_MODE = true. Never tap live ads on your own device.

7

Loading before init finishes, or showing before the ad is loaded

Loads fail and show_*() silently does nothing.

Do this instead: Wait for on_initialization_complete before load_*(), and check is_*_ready() before show_*().

8

Calling initialize() in every scene

It re-runs SDK start-up and stacks signal connections each time the scene loads.

Do this instead: Initialize once from a boot scene, guarded by is_initialized().

9

Changing scene only in on_interstitial_completed

If the ad fails to show, that signal never fires and the player is stuck.

Do this instead: Also connect on_interstitial_failed_to_show and continue from there.

10

Giving the reward when you call show_rewarded()

Players get the reward without watching, and failed shows still pay out.

Do this instead: Give rewards only in on_rewarded_earned.

11

Trusting auto-reload for rewarded ads

A skipped video can leave the rewarded ad unloaded, so the button stops working.

Do this instead: Call load_rewarded() when you need the ad and is_rewarded_ready() is false.

12

Forgetting to create the Banner_Android placement

Banners never load. Interstitial and Rewarded are created for you, Banner is not.

Do this instead: Create it under Monetization → Ad Units, named exactly Banner_Android (case-sensitive).

13

Hardcoding set_consent(true, true)

You tell Unity the player consented when they may not have, which is a privacy-law problem.

Do this instead: Pass the player's real choice from a consent screen, and check child-directed rules if your game targets kids.

14

Using Godot 3 signal syntax

UnityAds.connect("on_x", fn) is the old style, so your handlers never run.

Do this instead: Use UnityAds.on_x.connect(fn).

15

Testing in the editor or on desktop

There is no native plugin there, so nothing loads and the log says Plugin NOT found.

Do this instead: Export to a real Android device and read adb logcat.

16

Renaming the addon folder

The AAR path and autoload path are hardcoded to unity_ads_plugin.

Do this instead: Keep the folder at res://addons/unity_ads_plugin/.

17

Showing interstitials at the wrong moments

Ads at app launch or mid-gameplay hurt retention and reviews.

Do this instead: Show them at natural breaks such as level complete or game over, and keep rewarded ads optional.

18

Losing your release keystore

You cannot publish updates to the same Play Store app.

Do this instead: Back it up with its alias and passwords in more than one safe place.
